## Historical source

John E. Kreznar's 7 October 1969 memo, *Two Protocol Suggestions to Reduce
Congestion at Swap-Bound Nodes*, discusses early ARPANET hosts with slow
swapping between main memory and auxiliary storage. He proposed letting
a host inspect its IMP's incoming queue and select messages for efficient
delivery, such as serving a user already resident in memory first.

His second proposal was to keep cooperating programs in memory during a
multi-message file transfer. The memo also recognized that a time-sharing
system limits how long one user can monopolize memory.

The original text has no category field. As checked on 11 November 2026,
the RFC Editor catalogs RFC 19 in the Legacy stream with publication and
current status Unknown. The updates, updated-by, obsoletes and obsoleted-by
lists are all empty. This is a historical proposal.

## Applications

1. **Banking batch worker, selected.** Model grouping independent work by
   tenant when switching tenants incurs a cache or context loading cost.
2. **Cloud worker scheduling.** Compare FIFO and bounded batching for jobs
   requiring different loaded models or configuration contexts.
3. **Distributed queue experiment.** Verify that an optimization preserves
   each user's order while measuring changes in global completion order.

## Run

Use Go 1.22 or later from the repository root.

```sh
go run ./cmd/localitylab < examples/backlog.json
go run ./cmd/localitylab -html < examples/backlog.json > docs/index.html
go test -race ./...
go vet ./...
go build ./...
```

The example starts with user b resident and a backlog of a, b, a, b.
Each user switch costs three ticks and every message takes one tick.
FIFO requires four swaps and finishes at tick 16. With a burst cap of two,
locality runs messages 2, 4, 1, 3, requires one swap and finishes at tick 7.
User a's first message completes at tick 6 under locality and tick 4 under
FIFO. Lower total processing time can still delay an individual user.

## Model and tradeoffs

All messages are available at logical tick zero. The input array defines
the arrival order and message IDs. FIFO follows that order. Locality
prefers the earliest waiting message for the resident user until the
burst cap. At the cap, it selects the earliest waiting message for
another user. A switch resets the count. If no other user is waiting,
the current user can continue.

Every user's own message order is preserved. A finite backlog and a burst
cap make the exercise deterministic. The cap limits consecutive service
while another user waits, but it does not establish a latency SLA for a
particular user. Work with cross-user ordering dependencies needs additional
constraints before it can be reordered.

This educational simulation is inspired by the first proposal. It models
a single resident context with fixed switch and service costs. Historical
IMP queue control, host memory pinning, wire behavior, live arrivals,
failures and real latency measurements are outside its scope.
GitHub Pages serves the saved report generated by the local Go CLI.

Input contains a resident user, swap_cost 0–100, max_burst 1–20 and 1–200
messages. User names are 1–32 lowercase ASCII letters, digits or hyphens,
starting with a letter. The CLI rejects unknown fields, trailing JSON,
invalid parameters and input over 1 MiB. Output includes swaps, total
ticks, and each message's start and completion tick.

Tests check exact schedules and cost, the burst cap, per-user order,
message preservation, input immutability, single-user operation, zero
switch cost, invalid input and JSON and HTML entry points. CI regenerates
the HTML and compares it with the committed page. MIT licensed.
